12-factor deploys. Any hardware. None of the bloat.

Deploy Docker Compose apps to a cheap VPS or a box at home, the twelve-factor way: config lives on the server, every release is immutable, deploys have zero downtime and HTTPS is automatic. Your docker-compose.yml stays exactly as it is.

  1. 1

    Install the CLI macOS & Linux (Windows via WSL)

    $ curl -fsSL https://raw.githubusercontent.com/ddahan/dokwalt/main/install.sh | sh
  2. 2

    Set up your server any 64-bit Debian or Ubuntu, amd64 or arm64

    $ dokwalt server init you@your-server --email you@example.com
  3. 3

    Deploy in a folder with a compose.yaml

    $ dokwalt apps:create myapp dokwalt deploy dokwalt domains:add myapp.example.com --service web

Needs Docker on your computer and SSH key access with sudo on the server, ports 80 and 443 open. 1 GB of RAM is enough for a few small sites.

◆ Twelve-factor, by design

          
Apps, releases, config, pipelines.
On any hardware.

        


        

          
          

            

              
Zero-downtime deploys

              
The new version starts next to the old one, and traffic switches only once it passes its health checks. If it fails, the current version keeps serving and you see your app's own error logs. Databases are never duplicated.

            

          

            

              ● serving v2
              
            

            
          

          


          
          

            

              
Releases & instant rollbacks

              
Every deploy and config change is a numbered, immutable release. Rolling back is instant: the images are already on the server.

Native Docker Compose

              
No DokWalt file in your repo. Stateful services are detected and never duplicated; one-shot jobs run your migrations first.

            

            
db:
  image: postgres:17-alpine
  volumes: [pgdata:/var/lib/postgresql]
migrate:
  build: .
  command: ./manage.py migrate
web:
  build: .
  expose: ["8000"]
  depends_on:
    migrate:
      condition: service_completed_successfully

Nightly off-site backups

              
Every night, each Postgres database and DokWalt's own state go to Cloudflare R2 or any S3 storage — checksummed, pruned to 7 daily and 4 weekly, restored in one command. Run one Postgres for all your apps, still isolated from each other.
